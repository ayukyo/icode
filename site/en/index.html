Clear ownership, one source of truth

One ICODE family, two independent responsibilities

ICODE-SKILL defines what counts as correct. ICODE Agent is responsible for actually doing the work. This repository reads a pinned control plane without copying its state machine or outsourcing execution to another host agent.

Offline first

Reach a local self-check in four steps

Requires Git and Python 3.11+. The offline checks need no model key, and the HTTPS submodule URL makes a public recursive clone work without an SSH key.

terminal
# 1. Clone the agent and pinned control plane
git clone --recurse-submodules https://github.com/ayukyo/icode.git
cd icode

# 2. Create an isolated Python environment
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .

# 3. Inspect contracts, guard, and isolation
icode doctor

# 4. Run an offline handshake in a disposable path
mkdir -p /tmp/icode-handshake
icode handshake --workspace /tmp/icode-handshake
01

Start with capability facts

doctor separates “binary detected” from “backend works” and never calls the application guard a sandbox.

02

Connect a model later

Only model-backed commands need an endpoint and an external key. Contract and evidence checks stay offline.

03

Accept with exit codes

The model summary is not the completion criterion. Independent tests, control-plane gates, and receipts are.

Honest boundaries

What the evidence proves—and what it cannot

It can prove

Record consistency, artifact-to-ledger hash correspondence, and tampering within the covered files.

It cannot prove

Defect-free code, a real device run, deployed-version identity, or non-repudiation for an unanchored package.

Isolation facts

Reports enforced properties for a working kernel/container backend; otherwise says “application-level limits, not a sandbox.”

Website privacy

Static files only: no login, scripts, analytics, trackers, workbench connection, or ticket access.
