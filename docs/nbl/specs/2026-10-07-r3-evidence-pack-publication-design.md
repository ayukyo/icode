# R3 证据包发布与旧包恢复

范围：修复默认 `build_evidence_pack(clean=True)` 在写入、摘要计算或自校验失败时先删除旧包的问题。沿用现有包格式、`PackReport`、输入限制、工单/契约路径重叠保护和内置/独立校验器。用户已授权持续完善 R2/R3 并自主安排阶段，本片采用保持兼容的默认导出修复。

## 方案与调用链

默认导出在目标父目录创建唯一临时容器，用其 `pack` 子目录调用现有构建器；构建器仍负责全部输入、预算和契约检查。只有 `report.ok` 且 `report.selfcheck_ok` 才发布。旧目标存在时先将它改名到容器的 `previous`，再将新包改名到最终路径。第二次改名失败就恢复旧目标。无旧目标时直接发布暂存包。

报告的 `pack_dir` 始终是调用方的最终目标。自校验返回问题时返回原来的失败报告并说明未发布，保留旧包；构建或发布抛错时保留异常语义。恢复失败时保留备份、报告可恢复路径，绝不在清理临时目录时删除唯一旧包。发布成功但临时/备份清理失败时保留成功报告并加入清理警告。

`clean=False` 继续调用现有构建器，保留合并目录及清单语义。曾考虑两个模式都替换、仅增加失败后旧包恢复；前者改变合并兼容性，后者仍让旧包在构建期间消失，均不采用。

## 边界

暂存、备份和目标位于同一父目录，避免跨文件系统改名。沿用 `Path.resolve()` 的目标别名语义及源/目标重叠拒绝；既有非目录目标拒绝。正常 Python 异常可回滚，但两次目录改名不是连续可见的原子交换，不保证断电/进程被强杀时自动恢复。不新增并发导出锁，也不宣称防御其它进程替换路径。该片不改变隔离评分或自动模式。

## 验收

先以真实工单和已有有效旧包复现写入失败丢失旧包，再实现修复。回归覆盖：写入异常保留逐字节旧包；自校验失败不发布；旧目标备份失败仍保留旧包；发布改名失败回滚；回滚失败保留可恢复备份；正常发布移除旧成员并通过内置和独立校验；首次导出失败不留半包；清理失败有警告且新包有效；`clean=False` 保留已有成员。运行 evidence 套件、全仓 preflight、治理/官网/竞品检查和独立代码审查后提交推送。
